# Indian-Law Adapter v1 — Design Spec

**Date:** 2026-08-04
**Status:** Draft for user review
**Scope:** First domain adapter (Indian law) for the multi-adapter Gemma 4 31B system: data pipeline, SFT training, evaluation, export/serving validation, and repo rework. GRPO and further domains (medical) are separate future specs.

## Goal

Fine-tune a LoRA adapter on Gemma 4 31B that measurably improves Indian-law competence (statutes, case reasoning, legal drafting/format) over the base model, produced within ~29.9 Lightning.ai credits, servable in a product via hot-swappable adapters on one resident base.

## Non-negotiable constraints

- **Budget:** ≤ 29.9 Lightning.ai credits ($1 = 1 credit) for all GPU work; data work runs on free API tiers and the local machine only.
- **Licensing:** every training example must be commercially usable. No outputs from closed frontier APIs (OpenAI/Gemini/other proprietary providers) generated by us — their ToS bar training use regardless of publication. Frontier-quality data enters only via third-party public datasets under permissive licenses, or license-safe open-weight teachers.
- **Base model:** `unsloth/gemma-4-31B-it` (mirror of `google/gemma-4-31B-it`, Apache 2.0 — verified against primary sources 2026-08-04), **pinned to a specific revision** in code. Google rewrote the chat template 4× in 4 months; template drift breaks adapters silently. All future domain adapters train against the same pinned revision and target-module set so they stay swappable.
- **Python 3.12** (existing repo pin; unsloth requires ≥3.9,<3.15). `transformers==5.5.0` exact pin (Unsloth Gemma 4 requirement). Unsloth ≥ 2026.8.x (post-April Gemma 4 bug fixes).

## Architecture overview

```
[local/free tiers]                     [Lightning.ai GPU]          [anywhere]
corpus chunking ─┐
teacher ensemble ─┼→ judge filter → dataset (HF Hub, private)
curated datasets ─┘        │
                           └──────────→ L4 smoke → L40S SFT ─→ adapter (HF Hub)
                                                     │
                                        eval (BhashaBench, judge, guards)
                                                     │
                                        GGUF export → llama-server + adapter-active check
```

## 1. Data pipeline (target: ~50k examples)

### 1.1 Sources and mix

| Stream | Share | Contents |
|---|---|---|
| Grounded Indian-law synthesis | ~60% (~30k) | Generated from real Indian legal text: IRAC case analysis (~12k), statute-application QA (~6k), drafting/format tasks — petitions, notices, contracts, memos (~7k), judgment summarization + outcome reasoning with explanation (~5k) |
| Curated existing legal sets | ~16% (~8k) | IndicLegalQA (CC-BY-4.0, ~4k sample), PredEx instruction variants (Apache-2.0, ~3k), Aalap license-safe subsets only — CC-BY-NC Contract-Clause-Generation task stripped (~1k) |
| Frontier-output general/reasoning replay | ~24% (~12k) | OpenThoughts-114k R1 reasoning traces (Apache-2.0, ~5k), Nemotron-Post-Training-Dataset-v1 chat/STEM (CC-BY-4.0, ~4k), WildChat-1M GPT-4 conversations (ODC-BY, non-toxic English, ~3k) |

**All synthetic examples are emitted in the thinking format** — a reasoning trace followed by the answer; drafting tasks use plan-then-draft traces. Counting synthesis (30k) + PredEx explanations (3k) + OpenThoughts/Nemotron STEM traces (~8k), reasoning-trace share ≈ 80%, satisfying the gemma-4-thinking template's ≥75% reasoning guidance (non-reasoning remainder: WildChat chat, IndicLegalQA extractive QA, Aalap misc).

**Explicitly excluded** (and why): OpenHermes-2.5 (no coherent license), lmsys-chat-1m (contested user-content provenance), AM-DeepSeek-R1-Distilled (CC-BY-NC), tulu-3-sft-mixture unless its CC-BY-NC No-Robots subset is stripped (superseded here by Nemotron-v1 + WildChat), IL-TUR/ILDC/MILPaC (non-commercial), AIBE (no-derivatives; eval-only), Pile of Law / MultiLegalPile (non-commercial), LawInstruct (license ambiguity MIT-vs-CC-BY + constituent licenses; revisit only if resolved).

### 1.2 Grounding corpora (inputs to synthesis, not trained on directly)

- KanoonGPT/indian-case-laws — 17.1M HC judgments 1950–2026, eCourts-sourced, Apache-2.0 (cleaner provenance than IndianKanoon scrapes).
- NyayaAnumana (Apache-2.0) for outcome-labeled cases.
- Indian statutes via India Code (government works).
- The unvetted Prarabdha 6M-triplet set is admitted only after a 500-example manual/judge audit passes; otherwise excluded.

Chunking: structure-preserving, ~2,048 tokens per chunk (research-optimal for legal text), keeping citation context intact.

### 1.3 Teacher ensemble (all license-safe)

| Teacher | Access | Role |
|---|---|---|
| Nemotron 3 Ultra 550B | OpenRouter `:free` | Primary reasoning teacher (frontier-scale, NVIDIA open license) |
| DeepSeek / Qwen3.5 flagship | direct APIs, a few $ (optional, user's choice) | Second reasoning teacher for diversity |
| gpt-oss-120b | Cerebras free tier | Volume generation + second judge |
| Gemma 4 31B (self) | OpenRouter `:free` | Drafting/format volume (self-distillation is license-clean — Apache 2.0, verified) |

Throughput plan: batched generation (~10 examples/request), multiple providers in parallel (OpenRouter free: 50 req/day, or 1,000/day/model after a one-time $10 credit purchase — recommended, user's choice; plus Groq/Cerebras free tiers).

**Generation is resumable by design** (multi-day job across quota-limited providers): local state store (SQLite or JSONL — chunk ID → task type → status → output path), exponential backoff on 429/5xx, per-provider daily-budget tracking so quota is never double-spent, append-only raw output files, idempotent resume from any interruption. No external queue infrastructure — a state file is sufficient at this scale. Generation prompts randomize scenario/persona/legal-area per request for diversity, are difficulty-graded at generation time (easy/medium/hard labels — graded data is what worked in the German-law analogue), and require IRAC-structured reasoning for analysis tasks.

### 1.4 Quality gates (every synthetic example)

1. **Two-judge blind scoring** — two models from different families than the generator, pointwise 1–5 rubric (grounding faithfulness to the source chunk, legal-reasoning validity, format compliance, difficulty-label accuracy), pass = both judges ≥ 4 on every criterion. Judge order/identity hidden; rule-based floor checks (length, language, structure) run before judges to save quota.
2. **Citation verification** — every cited case/statute must exist in the grounding corpus (string + fuzzy match). Training on hallucinated citations is the field's worst documented failure (13–21% hallucinated citations in frontier models).
3. **MinHash dedup** across the full assembled set.
4. **Decontamination** — screen final training examples (not grounding chunks, which are never trained on verbatim) against BhashaBench-Legal, MMLU/IFEval guard sets, and the held-out split: 13-gram exact-match plus an embedding-similarity screen whose threshold is calibrated empirically during implementation (fixed cosine constants are embedding-model-specific). A shared statute quotation alone is not contamination — statutes are the domain being taught; the screen operates at question/answer level.
5. **Provenance metadata per example**: source dataset or grounding-chunk ID, teacher model, license tag, difficulty, judge scores. Enables later audits and selective removal.

Expected survival ~50–75%; generation targets are sized accordingly (~45–60k raw synthetic for ~30k accepted).

### 1.5 Held-out split

10% stratified by task type, chronologically-later judgments preferred for grounded examples. Never trained on; used for judge-based before/after eval.

## 2. Training

| Setting | Value | Why |
|---|---|---|
| Base | `unsloth/gemma-4-31B-it` @ pinned revision, QLoRA 4-bit (bnb dynamic) | 22 GB-class footprint; Gemma 4 quantizes well (official QAT); Unsloth patches Gemma 4 bugs |
| LoRA | r=32, α=32, dropout 0, all-linear (q,k,v,o,gate,up,down) | Domain adaptation needs all-linear + moderate rank (research: module choice > rank; r=8 notebook default is under-capacity) |
| LR | 2e-4, linear decay, 3% warmup, `adamw_8bit`, wd 0.001 | Unsloth Gemma 4 guidance |
| Batch | effective 16: per-device 2 × grad-accum 8 (fallback 1 × 16 if the long bucket OOMs) | Unsloth guidance; fits 48 GB |
| Loss | completion-only masking via the pinned revision's `response_template` | Standard; template markers `<|turn>user\n` / `<|turn>model\n` |
| Sequence | bucketed: 4,096 main (~90% of data), 8,192 long-doc bucket (~10%) | ~2× faster steps than uniform 8,192; mirrors Llama 3's 99.9%-short long-SFT mix |
| Epochs | 1, then eval-gated optional epoch 2 from checkpoint | Compute efficiency; >3 epochs is documented waste |
| Memory | `use_gradient_checkpointing="unsloth"`; `unsloth_tiled_mlp` if long bucket OOMs | 262k vocab doubles logit memory vs Llama; chunked CE mandatory |
| Reproducibility | seed 3407; full config committed to repo | |
| Checkpointing | push to private HF Hub repo every ~30 min / 500 steps; resume script | Survives session loss / credit exhaustion (Lightning force-stops at 0 credits) |
| Packing / NEFTune | off in v1 (packing conflicts with masking + Gemma 4 FA quirks) | Second-run experiments only |

**Runs:** (1) L4 smoke — ~1k-example subset, seq 2,048, verify loss curve, masking, checkpoint push/resume, ~2–3 h ≈ $1.50. (2) L40S main — opens with a ~20-step probe of the 8,192 long bucket (~$0.35; the L4 cannot host 31B at 8k, so this is the first place it's testable): if peak VRAM > 44 GB, enable `unsloth_tiled_mlp` **for the long-bucket phase only** (~3% total-time cost vs ~30% if hardcoded globally). Then 1 epoch ≈ 7–9 h ≈ $15–19.

## 3. Evaluation

| Check | Instrument | Gate |
|---|---|---|
| Indian-law competence | BhashaBench-Legal English (primary), Hindi (report-only), 4-bit inference on L4 | ≥ +3 points over base (EN) |
| Legal generation quality | LLM-judge on held-out split: blind, pointwise rubric, both-order averaged, two judge families | ≥ 55% win-rate vs base |
| Forgetting guard | MMLU 1k-sample + IFEval subset | within −2 points of base |
| Citation honesty | Spot-check: cited cases/statutes exist (sample of 200 generations) | no regression vs base |
| Adapter actually loaded | fixed prompt+seed output diff vs base at every serving deployment | outputs must differ |

Baseline (base model, no adapter) is measured once on all instruments before training. Eval inference runs on the L4 (~$1–2 total).

## 4. Export & serving validation

- Save adapter (`save_method="lora"`) and push to HF Hub.
- Convert with llama.cpp `convert_lora_to_gguf.py` (**build ≥ 2026-06-14** — earlier crashes on Gemma 4). Vision-tower weights are not targeted (text-only adapter), so llama.cpp's silent vision-LoRA drop is moot.
- Serve: `llama-server` with the QAT q4_0 GGUF base, `--lora-init-without-apply`, per-request `"lora": [{"id":0,"scale":1.0}]` — the verified hot-swap path; scales to N domain adapters on one resident base. Known cost: requests with different adapter configs don't batch together.
- **Not vLLM**: runtime LoRA for this architecture is nominally supported since v0.20.0 but functionally broken through v0.26.0 (adapters silently zeroed, fix PR unmerged ~4 months). Revisit when the fix merges; merged-weights serving remains the vLLM fallback (62.6 GB/domain — avoid).
- Known accepted residual: QLoRA's `+q` quantization-error term when the adapter is applied to a differently-quantized base (only measured datapoint: ~0.4 pp, within noise). The adapter-active check + eval gates catch any real degradation.

## 7. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Silent adapter failure (loads clean, serves base) | adapter-active diff check at every deployment; eval gates before/after |
| Chat-template drift on the HF repo | pinned revision everywhere; template bytes vendored into repo |
| Judge gaming / reward-style artifacts in filtering | blind pointwise judging, two families, rule-based floors, spot-audits |
| Ungrounded synthesis (Aalap failure mode) | every reasoning example grounded in a real chunk; difficulty grading; citation verification |
| Dataset licensing surprises | per-example license/provenance metadata; NC subsets stripped at ingest; excluded-sets list above |
| Lightning session loss / credit exhaustion | HF Hub checkpointing + resume script, tested during smoke |
| BhashaBench/Aalap are gated on HF | user accepts terms once before data phase (flagged in plan as a user action) |
| Safety drift from legal fine-tuning | general replay share; forgetting guard includes IFEval; spot-check refusals on a small harmful-request sample |

## 8. Out of scope (doors kept open)

- **GRPO phase 2:** path = merge SFT adapter to 16-bit → fresh RL LoRA (known-good sequence); reward sketch from research (citation-F1 + format + judge with rule floor). Needs its own budget.
- **Medical adapter:** same pinned base revision + target modules ⇒ swappable alongside law on one llama-server.
- **Hindi expansion:** BhashaBench-HI is reported from day one to seed this decision.
- **App integration** beyond a served, validated adapter.
