# Model-Parallel Lane (seq 6144) — Design

**Date:** 2026-08-07
**Status:** Approved by operator (brainstorming complete)
**Relationship to prior specs:** Adds a third training lane on top of the
platform decisions in `2026-08-05-kaggle-migration-design.md` and within the
v1 scope of `2026-08-06-project-charter-design.md`. The single-GPU and DDP
lanes (`configs/law_v1.yaml`, `configs/law_v1_ddp.yaml`) are untouched; the
main run remains DDP at seq 2048.

## 1. Motivation

Longer training sequences are VRAM-bound, and DDP cannot provide them: each
rank holds a full model copy, measured 13.6 GiB/rank at seq 2048 of 14.56
usable — seq 4096 projects to ~15.5 GiB/rank under the eager-CE fallback
(the fused-CE compile failure on torch 2.10 + sm_75 is stack-level, proven
by the Ministral runs). Single-GPU tops out around 3072-safe / 4096-unproven.

Splitting the model's layers across both T4s (`device_map: balanced`)
halves resident weights to ~5.2 GiB/GPU. At seq 6144 the worst GPU (the one
holding `lm_head`: +1.449 GiB CE spike, +logits) projects to ~11.5 GiB —
real margin. The cost is throughput: layer-sequential execution idles one
GPU at a time (~50% fleet utilization), forfeiting DDP's 2.14x. Kaggle
bills T4x2 sessions 1x wall-clock regardless, so quota cost per hour is
unchanged; tokens/week roughly halves versus DDP.

**Purpose of the lane:** the deferred long-tail phase (a small set of long
statute/judgment examples after the main 2048 run converges) and the seq-
ceiling evidence itself. It is not the primary lane.

**Load-bearing dependency:** accelerate's own `device_map` docs target
inference, not training. The training path here is unsloth's documented
multi-GPU support (their Magistral-2509 Kaggle notebook fine-tunes a 24B
split across 2x T4 via `device_map = "balanced"`). The PROBE gate (§6)
exists to validate that path empirically before anything else trusts the
lane.

`balanced_low_0` was considered and rejected: it keeps GPU 0 light, which
shifts weights onto the last GPU — exactly the device already carrying the
lm_head spike and logits. If the probe shows imbalance, the contingency is
an explicit `max_memory` skew that keeps the **last** GPU light (§6).

## 2. Config: `configs/law_v1_mp.yaml` (new)

Same base repo, pinned revision, ChatML markers, and LoRA block as the
other lanes (swappability rules). Differences:

- `model.device_map: balanced` — new optional field. Absent/null (all
  existing configs) preserves current behavior exactly.
- `train.smoke`: `max_seq_length: 6144`, `per_device_train_batch_size: 1`,
  `gradient_accumulation_steps: 5` (6144 x 5 = 30,720 tokens/step, matching
  the ~32,768 tokens/step of the other lanes), `max_steps: 60`,
  `save_steps: 25`, `dataset: data/smoke_v1.jsonl`.
- `hub.checkpoint_repo: tantan01/tuned-law-v1-qwen-ckpt-mp` (one repo per
  lane per base model).

Header documents launch command, PROBE-first gating, and expected numbers,
in the style of the DDP config header.

## 3. `sft.py` and `config.py` changes (all additive)

1. `ModelCfg` gains `device_map: str | None = None`. Passed to
   `FastModel.from_pretrained` only when set — `None` is byte-for-byte
   today's call, so the two qualified lanes are provably unaffected.
2. `--dataset` CLI override (mirrors `--max-steps`/`--save-steps` via
   `apply_overrides`) so PROBE can substitute the probe dataset without a
   separate config.
3. Fail-fast guards (pure functions, unit-tested, in the style of
   `check_ddp_visibility`):
   - `device_map` set and `WORLD_SIZE > 1` → abort (MP and torchrun are
     mutually exclusive).
   - `device_map` set and visible GPUs < 2 → abort (a leaked single-GPU
     mask would cram the full model onto one T4 and OOM mid-load).
   - Post-load split verification: when `device_map` is set, the set of
     devices holding model parameters must contain >= 2 CUDA devices;
     otherwise abort (a silently ignored device_map would look green until
     OOM).
4. Per-device VRAM reporting: keep `peak_vram_gb=` as the max across
   devices (the notebook's documented "< 14" eyeball stays valid) and add
   one `peak_vram_gb_dev{i}=` line per device. Single-GPU/DDP output gains
   one redundant line; nothing else changes.

## 4. Probe dataset helper (data module)

The pipeline does not pack sequences, so a probe only measures seq 6144 if
examples actually tokenize past 6144 — otherwise it is a false green. New
builder `build_probe`: concatenate smoke-dataset conversations into
multi-turn examples until each exceeds a character threshold of
`6 * 6144 = 36,864` message characters (>= 6 chars/token is conservative;
overshoot is free because the trainer truncates at `max_length`, undershoot
is the failure mode), emitting 8 examples to `data/probe_6k.jsonl`.
Multi-turn concatenation keeps ChatML valid; `train_on_responses_only`
masks the user turns as usual. One probe dataset serves any lane with
`max_seq_length <= 6144`.

Unit tests: character-threshold guarantee per emitted row, row count,
alternating-role message structure preserved.

## 5. Notebook integration

- `MP = False` flag beside `DDP`; both `True` raises immediately.
- `MP` selects `configs/law_v1_mp.yaml`, plain-python launcher (no
  torchrun), `CUDA_VISIBLE_DEVICES = "0,1"`.
- New lane-agnostic `MODE = "PROBE"`: args
  `--max-steps 2 --no-hub --dataset data/probe_6k.jsonl`, 45-minute
  timeout, builds the probe dataset beforehand.
- The whoami re-home cell derives and pre-creates the `-mp` repo the same
  way it does for the DDP lane.
- Docs cell and README lane table gain the MP row; resume-in-same-lane rule
  restated.

## 6. Gates, expectations, contingencies

Gate order: **PROBE → SAVETEST → (deferred) SMOKE/RESUME** when the
long-tail phase is planned.

PROBE green criteria: parameters observed on both GPUs; two full steps;
finite loss; worst-GPU peak with >= 1 GiB margin (expected ~11.5 GiB;
abort-and-rethink threshold ~13.5 GiB). Expected step time ~4-5 min at
ga=5 (~30.7k tokens/step at roughly single-GPU token rate); PROBE total
~20-25 min including model load.

Contingencies, in order:
1. Per-GPU peaks imbalanced → explicit `max_memory` skew keeping the last
   GPU light (mirror image of `balanced_low_0`), e.g.
   `{0: "13GiB", 1: "10GiB"}` — config-level change only.
2. OOM at 6144 → retry at 4096 (config edit only; the lane still beats
   both non-MP ceilings).
3. unsloth rejects device_map training on this stack → lane is falsified;
   document and stop (mirror of the Ministral disqualification write-up).

## 7. Out of scope

- Any change to the single-GPU or DDP lanes' behavior or hyperparameters.
- Sequence packing, FSDP, tensor/sequence parallelism.
- Long-tail dataset design and the decision to run the long-tail phase
  (charter-level, evidence-gated).
- Main-run plan changes: DDP at 2048 remains the throughput/primary lane.

## 8. Tests

- `config.py`: `device_map` parses; defaults to `None`; existing configs
  load unchanged.
- `apply_overrides`: dataset override applied/absent.
- Guard functions: MP x torchrun, MP x visible-GPU count, split
  verification (pure-function unit tests).
- `build_probe`: threshold, count, structure (§4).
- The template-drift tripwire and all existing tests remain untouched and
  must stay green.
