# tuned — Project Record at Cleanup (2026-08-02 to 2026-08-08)

**Date:** 2026-08-08
**Status:** Historical record, written immediately before the lane cleanup
**Scope:** Everything from the first commit (`954cfef`) through the 8B DDP gate
ladder going green (`31e98e6`). Sources: the full 66-commit history on `main`,
all five configs, both notebooks, the test suite, the four design specs and two
implementation plans in `docs/superpowers/`, and operator-supplied measurements
from live Kaggle sessions that were never committed. Where an operator claim

---

## Abstract

`tuned` is a $0-compute research project: fine-tune a QLoRA adapter for Indian
law on Kaggle's free 2x T4 tier and test whether license-safe, citation-verified
synthetic data measurably improves a small open model's domain competence. In
six days the project moved through three base models (Gemma 4 31B →
Ministral-3-14B-Reasoning → Qwen3), two platforms (Lightning.ai → Kaggle), and
five training lanes (single-GPU 14B, 14B DDP, 14B model-parallel, and finally
Qwen3-8B DDP), converging on one fully qualified lane: **Qwen3-8B under 2x T4
data-parallel at sequence length 8192**, which passed all four gates
(PROBE / SAVETEST / SMOKE / RESUME) on 2026-08-08 at ~438 tokens/s aggregate and
~13.2 GiB peak per rank against a 14.56 GiB ceiling. Four of the five configs,
three test modules, and the model-parallel and single-GPU code paths are about
to be deleted; this document plus `git log` is their only remaining record. The
one blocker to the main run is the dataset, whose spec is locked but whose build
has not started.

## 1. Goal and constraints

**Goal.** A LoRA adapter on HF Hub that is genuinely better at Indian law than
its base, produced at zero compute cost, plus a before/after evaluation report
against pre-registered thresholds (`3ad209d`, charter §2):

| Criterion | Instrument | Pre-registered threshold |
|---|---|---|
| Domain competence | BhashaBench-Legal (English), 4-bit inference on T4 | >= +3 points over base |
| Generation quality | Blind pointwise judge on held-out split, both-order averaged | >= 55% win-rate vs base |
| No forgetting | MMLU 1k-sample + IFEval subset | within -2 points of base |
| Citation honesty | 200-generation spot-check vs grounding corpus | no regression vs base |
| Usability | Adapter-only save, pinned base revision, shared target modules | loads and generates against the pinned base |

**Hard constraints.**

| Constraint | Value | Source |
|---|---|---|
| Budget | $0 GPU. Data work on free API tiers and the local machine only | charter §1 |
| Hardware | Kaggle free tier, accelerator **GPU T4 x2**, never P100 (sm_60 is below the unsloth/bitsandbytes floor) | `2026-08-05-kaggle-migration-design.md` §2 |
| VRAM | 15360 MiB/GPU nameplate, **14.56 GiB usable**; abort-and-rethink line drawn at 13.5 GiB | README history `11a645e`, notebook cell 10 |
| Precision | **fp16 only** — T4 (sm_75, Turing) has no bf16; flags explicit in code, never "auto" | `sft.py:87-88` |
| Quota | ~30 GPU-h/week, 12 h max per session, interactive kernels killed after 20 min idle | `11a645e` |
| Disk | `/kaggle/working` persists but caps at 20 GB; `/tmp` is scratch | `11a645e`, notebook cell 1 |
| Python | 3.12 (Kaggle image runs 3.12.13, verified live) | `7e76929`, `11a645e` |
| Licensing | Every training example commercially usable; no outputs from closed frontier APIs generated by us | `2026-08-04-indian-law-adapter-design.md` §1 |
| Swappability | Every domain adapter trains against the same pinned base revision with the same `lora.target_modules` scoping; adapter-only saves; never merge to 16-bit on Kaggle | README "Rules that keep adapters swappable" |

**Workflow.** Edit locally on Windows → `git push` → a Kaggle notebook clones
`github.com/Anant-T/Tuned` at `main` into `/tmp/tuned`, installs the pinned
deps, runs the repo's CLI, and pushes checkpoints to a private HF repo. The
bridge is one-way by design (`954cfef`): weights and datasets never enter git.

## 2. Chronological narrative

### Phase 0 — GitHub→Kaggle bridge scaffold (2026-08-02, `954cfef`..`7e76929`)

Four commits. `954cfef` created the one-way bridge: `.gitignore` refusing
weights and datasets, a two-cell `notebooks/kaggle_bootstrap.ipynb`, and
`where_am_i()` as the liveness probe (bump `__version__`, push, re-run cell 1,
check the printed version). `11a645e` recorded the first live-session facts:
Python 3.12.13, 2x Tesla T4 at 15360 MiB each, ~30 GPU-h/week, 12 h session cap,

survived every later redesign: **only `src/` crosses the bridge — the notebook
is a detached copy once imported into Kaggle**, so the bootstrap cell must stay
thin and all real logic must live in the package. `7e76929` pinned local Python
to Kaggle's 3.12.13.

### Phase 1 — Gemma 4 31B on Lightning.ai (2026-08-04, `f0bca16`..`ba14b15`)

`f0bca16` landed the Indian-law adapter v1 design spec: a ~50k-example dataset
(60% grounded synthesis / 16% curated / 24% replay), two-judge blind scoring,

flagged as having broken Gemma adapters four times in four months. `696de9a`
pinned `unsloth/gemma-4-31B-it-unsloth-bnb-4bit` @ `8e256fc6...` and added

### Phase 3 — Ministral disqualified, Qwen3-14B promoted (2026-08-06, `3ad209d`..`abf168d`)

`3ad209d` wrote the project charter: the research framing, staged-falsification
scope (Stage 1 at ~8–12k quality-dense examples, decision rule on the eval
delta), and the **throughput-sized dataset formula**
`N ≈ (usable GPU-h × measured tok/s × 3600) / avg tokens per example` — which
makes the smoke run's tokens/sec the input that sizes the entire main run.

`1464ddf` retired Ministral. Two manual runs OOMed at step 0 at **both** seq
2048 and seq 1024 with `PYTORCH_ALLOC_CONF=expandable_segments:True`. Root
cause chain (`docs/ministral-t4-disqualification.md`): unsloth_zoo's fused CE
uses `torch.func.grad_and_value`; on torch 2.10 + unsloth 2026.8.3
`torch._dynamo` raises "Unsupported functorch tracing attempt" and falls back to
the eager functorch path; that path materializes a full `lm_head` copy — the
failed allocation was exactly 1.25 GiB = fp16 131072 × 5120 — and it is
**sequence-length-invariant**, proven by reproducing the identical 1.25 GiB
request at half the sequence length. There was no headroom to absorb it because
Ministral ships **untied** embed + lm_head (~2.5 GB more residency than the
tied-weights fit estimate) plus a vision-tower wrapper, leaving a 13.5 / 14.56
GiB baseline before the loss. Everything upstream was green in the same runs:
the LoRA regex attached to `language_model` only (121.9M trainable = 0.87%), the
NaN guard filtered, the trainer configured. The unsloth#5677 save gate was never
even reached.

Qwen3-14B qualified the same day: single-GPU SAVETEST green at **208 s/step,
peak 12.9 GiB**, with a resume-complete Hub checkpoint. `ea42519` then added the
DDP lane, qualified by the 2026-08-06 DDP SAVETEST at **2.14x tokens/s vs
single-GPU, peaks 13.6/13.45 GiB per rank, grad_norm finite from step 3**.
`abf168d` wired the notebook DDP switch, the `whoami` checkpoint re-home, and
the rule that notebook cells never import the `tuned` package.

### Phase 4 — Model-parallel lane (2026-08-07, `19433d9`..`c0354b5`)

`19433d9` specced the MP lane, reversing the Aug-5 rejection of `device_map`.
The argument: DDP cannot buy sequence length because each rank holds a full
model copy (measured 13.6 GiB/rank at seq 2048; seq 4096 projects to ~15.5
GiB/rank under the eager-CE fallback). Splitting layers across both T4s halves
resident weights to ~5.2 GiB/GPU. Kaggle bills a T4x2 session at 1x wall-clock
regardless of GPUs used, so the split costs no extra quota — it trades DDP's
2.14x throughput for 3–4x sequence length. The spec explicitly rejected
`balanced_low_0` (it keeps GPU 0 light, shifting weight onto the device already
carrying lm_head + the CE spike + logits) and made the whole lane PROBE-gated,
since accelerate's `device_map` docs target inference, not training.

`0bb2720` implemented it: `model.device_map` config field (absent/null preserves
the existing lanes byte-for-byte), four fail-fast guards, `data/probe.py` (a
VRAM probe at seq N is a false green unless examples actually tokenize past N),
and notebook `MODE = "PROBE"`. `da5d570` recorded the **6144 PROBE green: peaks
5.98/12.56 GiB, 179.6 s/step at ga=5, ~162 tok/s upper bound**, and the operator
promoted MP to primary lane. `1090f6e` added `max_memory`, the `--max-seq-length`
override, and the `warmup_ratio → warmup_steps` conversion (transformers 5.5
deprecated the ratio; the probe logged lr=0). `93d7b17` corrected the skew
mechanism: `balanced` + `max_memory` computes ~equal per-GPU targets and caps
only *shrink* a GPU's share — the surplus went to CPU and bnb-4bit refused
("Some modules are dispatched on the CPU"). The working mechanism is
`device_map: sequential` + `max_memory: {0: "8GiB", 1: "13GiB"}`: sequential
fills dev0 to its cap first, so the spill to dev1 is small by construction.
`c0354b5` promoted the lane to seq 8192 on the strength of the **8192 PROBE:
param_devices on both GPUs, loss 0.607 finite, peaks 9.91/8.75 GiB (~4.6 GiB
margin on the worst GPU), 295.7 s/step at ga=5, ~131 tok/s**.

### Phase 5 — 8B DDP lane and the gate ladder (2026-08-07 to 2026-08-08, `8b1f0e0`..`31e98e6`)

`8b1f0e0` added the lane that won. The reasoning, recorded in the config
header: Qwen3-8B's dynamic 4-bit weights measure **6.97 GiB** (the repo's
`total_size`, not `params/2` — the naive halving estimate under-counts
quantization overhead); chunked cross-entropy is confirmed active on this stack
(the 14B MP lane's GPU1 peak of 8.75 GiB at seq 8192 proves logits never
materialize in full); the active path is unsloth's own chunked fused CE, because
cut-cross-entropy is dead code on sm_75 (its Triton kernels need 96KB shared
memory vs T4's 64KB). Default chunking (`n_chunks=4`) leaves a ~2.4–3.0 GiB
transient at the loss step; the notebook sets `UNSLOTH_CE_LOSS_N_CHUNKS=16`
before `import unsloth`, cutting it to ~0.7 GiB. Halving the per-token
footprint versus the 14B DDP lane was spent on **sequence length (2048 → 8192),
not throughput** — the direct consequence of the seq-length verdict (§4.6).

Then the ladder, one commit per gate: `de44b45` defaulted the notebook to the 8B
probe; `d4bda42` fixed the smoke-build child wedging at interpreter shutdown;
`d68505c` PROBE green at 12.80/13.00 GiB; `70b5df6` SAVETEST green with the Hub
push verified; `f98a900` hardened the notebook four ways (bounded token hunt,
xet turbo, async pushes, launcher cleanup); `0e25e4f` added the divergence guard;
`93a5058`/`16d8f00` added the staged-snapshot fast path and `stage_model.ipynb`;
`ebbfd47` added opt-in W&B; `31e98e6` recorded SMOKE green and advanced to
RESUME with `--max-steps 64`.

### 4.4 Qwen3-14B, 2x T4 DDP at seq 2048 (2026-08-06) — qualified, killed by the seq-length verdict

**Shipped as:** `configs/law_v1_ddp.yaml` — identical to `law_v1.yaml` in model
pin, markers, think tags, and LoRA block (asserted in
`test_ddp_config.py::test_ddp_matches_primary_except_ga_and_repo`), differing
only in `gradient_accumulation_steps: 8` (× 2 ranks = effective batch 16,
identical optimization to the single-GPU plan) and ckpt repo
`tantan01/tuned-law-v1-qwen-ckpt-ddp`. Launch:

```
CUDA_VISIBLE_DEVICES=0,1 torchrun --nproc_per_node=2 -m tuned.train.sft \
    --config configs/law_v1_ddp.yaml --mode smoke
```

The `CUDA_VISIBLE_DEVICES` override is mandatory — see §7. `ddp_find_unused_parameters`
is forced `False` (`sft.py:94`): TRL defaults it to `True` under DDP, buying an
extra autograd-graph traversal every step for nothing, since every LoRA
parameter gets a gradient each step.

**Measured (2026-08-06 SAVETEST):**

| Metric | Value |
|---|---|
| Throughput | **2.14x** tokens/s vs single-GPU (≈ 338 tok/s; ~100 s/step) |
| Peaks | 13.6 / 13.45 GiB per rank of 14.56 (~1 GiB headroom) |
| grad_norm | nan on steps 1–2 (fp16 GradScaler calibration, benign), finite from step 3 |
| Checkpoint | rank-0 Hub save, resume-complete |

**Verdict / why it ended:** technically qualified and never falsified — killed by
a quality argument, not a failure. The economics: a T4x2 session bills at 1x
wall-clock regardless of GPUs used, so the second GPU is free; DDP spends it on
throughput, MP spends it on sequence length. At 13.6 GiB/rank at seq 2048, DDP
has no room to buy sequence length at all — seq 4096 projects to ~15.5 GiB/rank
under the eager-CE fallback. On 2026-08-07 the operator ruled that **truncating
legal documents at 2048 trains hallucination**, which no amount of throughput
compensates for, and that DDP's ~2.6x speed advantage over 8192-MP is
*concurrency, not an attention tax* — i.e. it is a property of running two
replicas, not evidence that long sequences are intrinsically expensive. That
verdict retired the 2048 lane. **[uncommitted — the verdict itself is not
written anywhere in the repo; its fingerprints are the MP promotion (`1090f6e`)
and the 8B lane's decision to spend its memory savings on sequence length rather
than throughput (`8b1f0e0` config header).]**

## 5. The gate ladder

The ladder is the project's core operating discipline: **no lane is trusted
until all four gates are green, in order, in the same lane's checkpoint repo.**
Each gate is a `MODE` in `notebooks/kaggle_smoke.ipynb` cell 9, which maps to
CLI arguments on top of the config's `train.smoke` block.

| Gate | CLI args | Watchdog | Purpose | Green means |
|---|---|---|---|---|
| **PROBE** | `--max-steps 2 --no-hub --dataset data/probe_long.jsonl [--max-seq-length PROBE_SEQ]` | 45 min | VRAM ceiling at the real sequence length | 2 full steps, finite loss, worst-device peak >= 1 GiB margin (abort-and-rethink at ~13.5 GiB); MP additionally: `param_devices` lists both GPUs. **No Hub push by design** — `--no-hub` strips the repo from the config, not just the preflight, so a probe can never touch or depend on the lane's checkpoints |
| **SAVETEST** | `--max-steps 4 --save-steps 2` | 45 min | LoRA save + Hub push path | `last-checkpoint/` visible in the re-homed ckpt repo; `grad_norm` finite by step 3 |
| **SMOKE** | (none — config defaults: 60 steps, save every 25) | 11 h | Sustained training health and the throughput measurement that sizes the main run | 60/60 steps, loss trending down, no NaN, `peak_vram_gb` < 14; record `approx_tokens_per_sec` |
| **RESUME** | `--resume --max-steps 64` | 11 h | Session-loss survival (the 12 h cap mechanism) | run in a **fresh** session; first logged step is **61**, not 1; 4 steps complete with finite grad_norm |

**Two design notes that make the ladder honest.**

*The probe dataset.* The pipeline does not pack sequences, so a VRAM probe at
seq N only measures N if examples actually tokenize past N — otherwise it is a
false green. `tuned.data.probe` concatenates smoke rows into multi-turn
conversations until each exceeds `chars_per_token × target_tokens` characters
(6 chars/token is conservative for English/reasoning text; overshoot is free
because the trainer truncates at `max_length`, undershoot is the failure mode).
Multi-turn concatenation keeps ChatML valid and `train_on_responses_only` masks
the user turns as usual. Tested for the character guarantee, row count, and
alternating-role structure.

*The at-max-steps no-op.* SMOKE's final checkpoint sits **at** `max_steps=60`.
A bare `--resume` would load it, find `global_step == max_steps`, and exit
without taking a single step — rc=0, no error, a **no-op false green**.
`--max-steps 64` forces 4 real steps, which is the only thing that proves the
optimizer, GradScaler, and RNG state actually reloaded. This is asserted in
`test_notebook.py` so it cannot be quietly reverted.

## 6. Training-code architecture (what the gates run)

`src/tuned/train/sft.py` is the single entrypoint for every lane. Its shape is
dictated by the failure modes it has to survive:

- **Preflight before any GPU import.** Config load (strict — refuses an unpinned
  revision), hub-repo checks, MP/torchrun conflict check, `max_memory`-requires-
  `device_map` check, version printout, then `nvidia-smi`-based compute-capability
  gate (read via subprocess *before* any CUDA library loads, so a P100 session
  dies in milliseconds rather than after a model download).
- **Unsloth imported first**, before torch/transformers/trl, so its patches
  apply. Immediately after: the `ALLOW_PREQUANTIZED_MODELS` guard — if
  bitsandbytes' native kernels fail to load, unsloth 2026.8.3's loader silently
  strips the `-unsloth-bnb-4bit` suffix **and drops `revision=`**, turning a
  doomed run into a ~28 GB fp16 re-download inside the watchdog. This ordering
  is enforced by `test_pins.py`, which asserts the guard's source position
  precedes `FastModel.from_pretrained`.
- **`resolve_model_source`** prefers a pre-staged local snapshot
  (`TUNED_MODEL_PATH`) over the hub repo. A local path carries no revision — and
  loading by path never touches the network, sidestepping both the hub-stall
  failure class and unsloth's history of ignoring `HF_HUB_OFFLINE`.
- **Post-load assertions.** LoRA module sample printed; any module matching
  "vision" aborts the run (unsloth#5677 risk). With `device_map` set,
  `param_devices` is printed and `check_model_split` runs.
- **Explicit precision.** `fp16 = not bf16_supported`, `bf16 = bf16_supported` —
  correct on T4, still correct on a newer GPU. `dtype=torch.float16` at load.
- **`warmup_ratio` → `warmup_steps`** conversion in `build_sft_config`:
  transformers 5.5 deprecated the ratio and logged lr=0 in the 2026-08-07 MP
  probe. The ratio stays the config's semantic knob.
- **`report_to`** is `"wandb"` iff `WANDB_API_KEY` is in the environment, else
  `"none"` — fail-open, so a notebook without the secret behaves exactly as
  before.
- **Divergence guard** (`_NonFiniteWindow` + `_NonFiniteGuard`, `0e25e4f`). Keyed
  on `grad_norm`, never loss: `logging_nan_inf_filter` defaults `True` and
  rewrites nan losses in logs, so loss *cannot* show divergence. A 2-step grace
  window covers DDP GradScaler calibration (observed nan on steps 1–2 of both
  green 8B gates); after that, 3 **consecutive** non-finite values abort, because
  a lone nan is ordinary GradScaler backoff. Unparseable values neither advance
  nor reset the streak. The callback must **raise**, not set
  `control.should_training_stop` — that flag ends the run rc=0, the exact signal
  normal completion uses, so the supervisor would read a divergence as green.
- **Telemetry on exit.** `train_loss`, `peak_vram_gb` (max across devices) plus
  one `peak_vram_gb_dev{i}` line per device, `train_runtime_s` and
  `approx_tokens_per_sec` (suppressed on `--resume`, where the step count is not
  the full run).

## 9. Dataset — spec locked, build not started

**This is the only blocker to the main run.** Every gate to date has run on
generated smoke/probe data: `data/smoke_v1.jsonl` (~1k examples streamed from
OpenThoughts-114k, Apache-2.0, wrapped in the config's think tags) and
`data/probe_long.jsonl` (8 concatenated long examples). `/data/` is gitignored;
both are rebuilt from `src/tuned/data/` at the start of every session.

**Spec as of 2026-08-07.** This is an operator decision that **supersedes** the
Aug-6 charter's Stage-1 dataset row (`3ad209d`, charter §5, which specified
~8–12k examples at a single 2048-or-4096 bucket with packing off in v1). The
supersession was never committed to the repo — the charter text still reads as
originally written — so the table below is the governing spec and the charter's
row is dead:

| Dimension | Value |
|---|---|
| Volume | 15–20k Indian-law examples |
| Mix | 60% grounded synthesis / 16% curated / 24% replay |
| Curated sources | IndicLegalQA (CC-BY-4.0), PredEx instruction variants (Apache-2.0), Aalap license-safe subsets only (CC-BY-NC contract-clause task stripped) |
| Replay sources | OpenThoughts-114k (Apache-2.0), Nemotron-Post-Training-v1 (CC-BY-4.0), WildChat-1M (ODC-BY, non-toxic English) |
| Reasoning traces | **>= 80% hard floor** |
| Bucketing | single 8192-token bucket; **drop, never truncate**, anything over 8192 |
| Packing | builder ships **UNPACKED**; TRL packs at train time (`packing=True`, default `bfd`). Pre-packing in the builder would be silent contamination. CPU-side assert via `find_packed_sequence_indices` |
| Synthesis temperature | T = 0.6–0.8 (not 0.2–0.3) |
| Rejection gates | citation set-difference, cross-code rejection |
| Rejected approach | replay length-normalization |
| Builder gates (3) | tokenized-length histogram (p50/p90/p99); label-mask assert; `pad == <\|endoftext\|>` assert |
| Size | ~37–50M tokens |

**Open pre-main-run TODOs implied by this spec.** Two pieces of the packing
decision exist only on paper: `build_sft_config` **does not set `packing`** —
train-time TRL packing (`packing=True` + default `bfd`) is specified but not yet
implemented in `sft.py` — and the CPU-side packing pre-flight assert via
`find_packed_sequence_indices` is likewise unwritten. Both must land before the
main run, because an unpacked run against a drop-never-truncate 8192 dataset
would silently waste most of every batch, and a builder that pre-packs instead
would be silent contamination.

**Quality machinery inherited unchanged from the Aug-4 spec:** two-judge blind
pointwise scoring (Stage 1 trims to rule floors + one judge on every example
with a 10% second-judge blind audit), citation verification against the
grounding corpus on **every** example (this is the method under test, so it is
never trimmed), MinHash dedup, 13-gram + calibrated-embedding decontamination
against BhashaBench-Legal and the guard sets, a 10% stratified held-out split,
and per-example provenance metadata (source/chunk ID, teacher, license tag,
difficulty, judge scores). Grounding corpora: KanoonGPT/indian-case-laws
(Apache-2.0), NyayaAnumana (Apache-2.0), India Code statutes. Explicitly
excluded license sets are listed in the Aug-4 spec §1.1 and remain binding.

**Main-run projection from the measured 8B throughput:**

| Quantity | Value |
|---|---|
| Measured aggregate rate | ~438 tok/s |
| Tokens per GPU-hour | ~1.58M |
| Dataset size | ~37–50M tokens |
| Optimizer steps per epoch (at 32,768 tok/step) | ~1,130–1,530 |
| GPU-hours per epoch | **~23–32 h ≈ one 30 GPU-h quota-week** |

The charter's sizing formula
`N ≈ (usable GPU-h × measured tok/s × 3600) / avg tokens per example` now has
its measured input, and the answer is that one epoch of the locked dataset is
one quota-week. Resume-from-Hub between weeks — proven by the RESUME gate — is
therefore load-bearing, not a nicety.
